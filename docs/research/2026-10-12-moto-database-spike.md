Headline: **DynamoDB data-plane is the best-modelled service** (queries, conditions, transactions, streams, backups, PITR restore, validation limits). **RDS stores and returns almost every field but simulates no behaviour** (Multi-AZ standby, failover on reboot, encryption rules, class and storage validation are absent), and cross-region replicas are half-modelled. **ElastiCache replication groups are a thin fake** (node count ignored, no modify, no failover, no serverless). **moto's CloudFormation silently skips `AWS::SecretsManager::Secret`, `AWS::ElastiCache::SubnetGroup`, `AWS::ElastiCache::ReplicationGroup`, `AWS::RDS::DBCluster`, `AWS::DynamoDB::GlobalTable`**, and drops several important properties on the types it does deploy (`DeletionProtection` and `VPCSecurityGroups` on `DBInstance`, TTL/PITR/SSE/TableClass on `Table`, `ManageMasterUserPassword`). The data tier therefore has to be verified on the rendered template (`cfn.resources(...)`) plus cfn-lint, with moto used only for what it really applies.

**A new cfn-lint gotcha:** `EngineVersion: '16.4'` on postgres is flagged **W3691 "deprecated and cannot be used to create new RDS DB instances"**, and so are `16`, `16.3`, `16.8`, `17`, `17.4`. Use a current minor (`17.5`+ or `16.9`+, `15.13`+, `14.19`); the template in `data.yaml` is lint-clean with `17.9`.

## What the plan can rely on
- **DynamoDB data plane**: create_table (PPR and PROVISIONED, partition + sort key, GSI and LSI at creation), query (`begins_with`, `BETWEEN`, filter with `Count`/`ScannedCount`, `IndexName`, `ScanIndexForward`, `Limit` + `LastEvaluatedKey` pagination), scan (limit, segments), `ConsistentRead` on a GSI rejected, LSI after creation rejected (no API), conditional put/update/delete with `ConditionalCheckFailedException` and `ReturnValuesOnConditionCheckFailure`, `ReturnValues`, `transact_write_items` / `transact_get_items` (limit 100, rollback, `CancellationReasons`, duplicate-item rejection), `batch_write_item` / `batch_get_item`, empty-key and 2048-byte key validation, item size rejection (about 400,000 bytes), deletion protection, tags.
- **DynamoDB streams** (`dynamodbstreams`: describe_stream, shard iterator, get_records with correct old/new images), **PITR configuration and restore** (`update_continuous_backups`, `restore_table_to_point_in_time`), **on-demand backups** (`create_backup`, `restore_table_from_backup`), **TTL configuration** (`update_time_to_live`, `describe_time_to_live`), SSE with an explicit KMS key.
- **DAX** basic CRUD of a cluster (`create_cluster`, `describe_clusters`, `increase_replication_factor`, `delete_cluster`) for shape-only checks.
- **RDS**: `create_db_subnet_group`; `create_db_instance` fields (MultiAZ, StorageEncrypted, KmsKeyId, BackupRetentionPeriod, DeletionProtection, gp3, IAM auth, CopyTagsToSnapshot, VpcSecurityGroupIds, PubliclyAccessible) read back from describe; **`DeletionProtection` enforced on `delete_db_instance` and `delete_db_cluster`**; **`ManageMasterUserPassword` creating a Secrets Manager secret and returning `MasterUserSecret`**; snapshots, encrypted snapshot copy, restore from snapshot, point-in-time restore (as API shape); same-Region read replicas with `ReadReplicaDBInstanceIdentifiers`; engine-mismatch check on cluster members; stop/start.
- **Aurora**: `create_db_cluster` (Endpoint, ReaderEndpoint, ServerlessV2 config stored), instances joining a cluster with writer/reader roles, **`failover_db_cluster` moving the writer role**, global cluster create/describe, cluster snapshots and restores, RDS Proxy create/register/describe/modify target group.
- **ElastiCache**: `create_replication_group` field round-trip (failover, MultiAZ, encryption flags, AuthTokenEnabled, snapshot retention, tags, `PrimaryEndpoint`), `create_cache_subnet_group` (name and VPC only), `delete_replication_group`, memcached `create_cache_cluster` field round-trip.
- **Secrets Manager**: create/get/put/describe, staging labels, tags, KMS key, delete window rules (7 to 30 days) and restore, replication to another Region, resource policy, random password, rotation *configuration* (set via `rotate_secret` with a Lambda ARN, or without; read `RotationEnabled` / `RotationRules` / `RotationLambdaARN`).
