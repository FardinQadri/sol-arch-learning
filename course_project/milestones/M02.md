# M02 — The network for shortly-infra

You build the second layer: the network the app lives in. One VPC, three tiers of subnets (public, app, data) in two Availability Zones, internet and NAT gateways, route tables, security groups chained by reference, free gateway endpoints for S3 and DynamoDB, and VPC flow logs. All of it goes in one CloudFormation template.

The template costs nothing while it is only a file and the tests run. It costs money only if you deploy it: NAT gateways and their public IPv4 addresses bill by the hour, whether or not any traffic flows. See `DEPLOY.md` before you deploy.

Do this milestone in week 02, after the VPC notes and drills. The week 02 drill on planning subnet sizes (drill 02) is the tool you need for M02.1.

The tests look for exact names. Use these.

| What | Value |
|---|---|

| Parameters | `Prefix` (default `shortly`), `Env` (`lab` or `prod`), `VpcCidr` (default `10.20.0.0/16`) |
| Condition | `IsProd`: true when `Env` is `prod` |
| `Vpc` | `AWS::EC2::VPC` |
| `PublicSubnetA`, `PublicSubnetB` | `AWS::EC2::Subnet` (load balancers and NAT gateways) |
| `AppSubnetA`, `AppSubnetB` | `AWS::EC2::Subnet` (the app, private) |

| `NatEipB`, `NatGatewayB` | the same for `PublicSubnetB`, with `Condition: IsProd` |

| `AppRouteTableA`, `AppRouteTableB` | one table per AZ for the app subnets |
| `DataRouteTable` | one table for both data subnets |
| routes | `AWS::EC2::Route` resources (any ids) |
| associations | one `AWS::EC2::SubnetRouteTableAssociation` per subnet (any ids) |
| `AlbSecurityGroup` | `AWS::EC2::SecurityGroup` |
| `AppSecurityGroup` | `AWS::EC2::SecurityGroup` |
| `DbSecurityGroup` | `AWS::EC2::SecurityGroup` |

| `S3Endpoint` | `AWS::EC2::VPCEndpoint`, a Gateway endpoint |
| `DynamoDbEndpoint` | `AWS::EC2::VPCEndpoint`, a Gateway endpoint |
| `FlowLogsLogGroup` | `AWS::Logs::LogGroup`, name `/${Prefix}/vpc-flow-logs` |

| `VpcFlowLog` | `AWS::EC2::FlowLog` |

The template also has eight Outputs, each with an export. They are listed in M02.6.

"A" is the first Availability Zone of the Region and "B" is the second. The tests fill in `Prefix=shortly`, account `111122223333` and region `us-east-1`. They check `Env=prod` and `Env=lab` separately.

## M02.1 — the VPC and six subnets

Plan first, write second. The test checks:

- parameters `VpcCidr` (default `10.20.0.0/16`), `Prefix` and `Env` exist;
- `Vpc` takes its `CidrBlock` from `VpcCidr` and has `EnableDnsSupport` and `EnableDnsHostnames` both on (VPC endpoints and RDS need DNS);
- the six subnets exist in `Vpc`. Subnet A is in the first AZ and subnet B in the second;
- every subnet lies inside the VPC, and no two subnets overlap;
- each subnet is big enough. Remember AWS keeps 5 addresses in every subnet:

  | Tier | Usable IPs needed |
  |---|---|
  | public | at least 250 |
  | app | at least 1,000 |
  | data | at least 250 |

- the four private subnets (app and data) never set `MapPublicIpOnLaunch: true`;
- your repo `README.md` has a `## Network plan` section that lists each of the six subnets with its CIDR block. Write the exact block text, for example `10.20.0.0/22`. A table is a good format.

A subnet looks like this. The Availability Zone comes from the Region, not from a typed name, so the template works in any Region:

```yaml
PublicSubnetA:
  Type: AWS::EC2::Subnet
  Properties:
    VpcId: !Ref Vpc
    AvailabilityZone: !Select [0, !GetAZs '']
    CidrBlock: !Select [0, !Cidr [!Ref VpcCidr, 4, 8]]   # example numbers: plan your own
    Tags:
      - {Key: Name, Value: !Sub '${Prefix}-public-a'}
```

Moto (the offline AWS) cannot run `!Cidr`. The test tools expand it for you, so using `!Cidr` is fine and the tests still see real blocks. Typing the blocks by hand also passes.

## M02.2 — internet gateway, NAT gateways and route tables

This step decides who can reach the internet. The test checks:

- `InternetGateway` exists and is attached to `Vpc`;
- with `Env=prod` there are two NAT gateways, `NatGatewayA` in `PublicSubnetA` and `NatGatewayB` in `PublicSubnetB`. With `Env=lab` there is only `NatGatewayA`. Each NAT gateway has an Elastic IP: `AllocationId: !GetAtt NatEipA.AllocationId`;
- each subnet is associated with its table: both public subnets with `PublicRouteTable`, `AppSubnetA` with `AppRouteTableA`, `AppSubnetB` with `AppRouteTableB`, both data subnets with `DataRouteTable`;
- `PublicRouteTable` has exactly one default route (`0.0.0.0/0`) and it goes to `InternetGateway`;
- `AppRouteTableA` has its default route to `NatGatewayA`. `AppRouteTableB` goes to `NatGatewayB` in prod, and to `NatGatewayA` in lab;
- `DataRouteTable` has no routes of your own: no internet, no NAT. Only the built-in local route.

The second NAT gateway exists only in prod, so it carries a condition. The route in the app table in AZ B picks its target with `!If`:

```yaml
Conditions:
  IsProd: !Equals [!Ref Env, prod]

Resources:
  NatGatewayB:
    Type: AWS::EC2::NatGateway
    Condition: IsProd
    Properties:
      SubnetId: !Ref PublicSubnetB
      AllocationId: !GetAtt NatEipB.AllocationId

  AppDefaultRouteB:
    Type: AWS::EC2::Route
    Properties:
      RouteTableId: !Ref AppRouteTableB
      DestinationCidrBlock: 0.0.0.0/0
      NatGatewayId: !If [IsProd, !Ref NatGatewayB, !Ref NatGatewayA]
```

(`NatEipB` has the same `Condition`.) In the exam, one NAT gateway per AZ is the highly available design, because a NAT gateway lives inside one AZ. The lab accepts one shared NAT gateway to halve the hourly cost.

## M02.3 — security groups chained by reference

Security groups are stateful firewalls on the network interface. Instead of IP ranges, the inner groups name the outer group as the source. The test checks that all four groups exist in `Vpc` and that their inbound rules are exactly:

| Group | Inbound |
|---|---|
| `AlbSecurityGroup` | TCP 443 from `0.0.0.0/0`. Port 80 from `0.0.0.0/0` is allowed too, and nothing else |
| `AppSecurityGroup` | TCP 8000 from `AlbSecurityGroup` only |
| `DbSecurityGroup` | TCP 5432 from `AppSecurityGroup` only |
| `CacheSecurityGroup` | TCP 6379 from `AppSecurityGroup` only |

Rules can be inline (`SecurityGroupIngress`) or separate `AWS::EC2::SecurityGroupIngress` resources. The test also loads your rules into the course's network model (`netsim`) and checks the paths: the internet reaches the ALB on 443, the ALB reaches the app on 8000, the app reaches the database on 5432 and the cache on 6379. The internet must not reach the app or the database, the ALB must not reach the database, and nobody gets SSH (22) into the app.

A rule that refers to another group:

```yaml
DbSecurityGroup:
  Type: AWS::EC2::SecurityGroup
  Properties:
    GroupDescription: PostgreSQL from the app tier only
    VpcId: !Ref Vpc
    SecurityGroupIngress:
      - {IpProtocol: tcp, FromPort: 5432, ToPort: 5432, SourceSecurityGroupId: !GetAtt AppSecurityGroup.GroupId}
```

## M02.4 — gateway endpoints for S3 and DynamoDB

Private subnets should reach S3 and DynamoDB without a NAT gateway: it is cheaper and the traffic stays on the AWS network. Gateway endpoints are free. The test checks that `S3Endpoint` and `DynamoDbEndpoint`:

- are `Gateway` endpoints (an Interface endpoint costs money);
- have `ServiceName` `com.amazonaws.<region>.s3` and `com.amazonaws.<region>.dynamodb` (build it with `!Sub` and `${AWS::Region}`);
- belong to `Vpc` and are on all three private route tables: `AppRouteTableA`, `AppRouteTableB` and `DataRouteTable`.

`S3Endpoint` also needs an endpoint policy (`PolicyDocument`). The policy must let the app read from this account's buckets, and must not let the endpoint reach buckets owned by other accounts. The test asks the course's policy evaluator both questions: a bucket in account `111122223333` is allowed, a bucket whose `aws:ResourceAccount` is another account is not. This stops data leaking out through your VPC to a bucket an attacker owns.

## M02.5 — flow logs

Flow logs record which connections were accepted or rejected. The test checks:

- `FlowLogsLogGroup` is named `/${Prefix}/vpc-flow-logs` and has `RetentionInDays` between 1 and 90;
- `VpcFlowLog` logs the whole VPC (`ResourceType: VPC`, `ResourceId: !Ref Vpc`), with `TrafficType` `ALL` (or `REJECT`), to CloudWatch Logs, using `FlowLogsLogGroup` and `FlowLogsRole.Arn` as `DeliverLogsPermissionArn`;
- `FlowLogsRole` can be assumed only by the service `vpc-flow-logs.amazonaws.com` (not EC2);
- the role may call `logs:CreateLogStream` and `logs:PutLogEvents` on its own log group's streams, and on no other group.

This role is IAM, so apply what you learned in M01: name the actions and the resource, no `*`.

## Hints (read only when stuck)

- Plan the blocks on paper first, with drill 02's function: the biggest subnets first, so every block starts on its own boundary. Check the usable count of each (size minus 5).
- `!Cidr [!Ref VpcCidr, count, bits]` cuts the VPC into `count` equal blocks. `bits` is the number of host bits: 8 gives /24 from a /16, 10 gives /22. Two sizes need two `!Cidr` calls, and `!Select` picks the block by index. Take care that blocks from the two calls do not overlap.
- Routes and Elastic IPs that need the internet gateway should have `DependsOn: GatewayAttachment` (use your attachment's id). Without the attachment, they can be created too early.
- Security group ids: `!GetAtt AppSecurityGroup.GroupId` or `!Ref AppSecurityGroup` both give the id.
- For the S3 endpoint policy, allow `s3:*` for the principal `'*'` and add a `StringEquals` condition on `aws:ResourceAccount` with `!Ref AWS::AccountId`.
- Log groups keep logs forever unless you set `RetentionInDays`. Set it.
- `Env` and `Prefix` must be used somewhere or `cfn-lint` warns. Use `Prefix` in names and tags.
- Why does the lab use one NAT gateway? Each costs about 0.045 USD per hour plus 0.005 USD per hour for its public IPv4 address, whatever the traffic (illustrative prices). Prod pays for two to survive the loss of an AZ.
- When a test fails, read its message first. It names the resource or the subnet that went wrong.

## Why this matters in the exam

- **Three tiers, two AZs:** public subnets hold only what must face the internet (load balancers, NAT). Everything else is private. A subnet is in exactly one AZ.
- **NAT per AZ:** a NAT gateway is zonal. For high availability, make one per AZ and route each AZ's private subnets to its own. (Changed: AWS has since added a regional NAT gateway mode. The exam answer is still one per AZ.)
- **Security groups by reference:** chaining groups beats IP ranges. SGs are stateful and allow-only. Network ACLs are stateless.
- **Gateway endpoints:** S3 and DynamoDB are the two gateway endpoints, free, and a route in the table. Interface endpoints cost money. An endpoint policy limits what goes through.
- **Flow logs:** they record accepted and rejected connections, to CloudWatch Logs, S3 or Firehose. They do not capture packet contents.
